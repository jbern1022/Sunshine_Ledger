## The run (Joe at docker-host, Claude watching AWS)

Write each time down in the table at the end.

**T0: take home off the internet.** On docker-host:

```bash
docker stop sunshineledger-cloudflared-1 sunshineledger-cloudflared2-1
```

Only the tunnel stops. The database, API and nightly keep running at home, so
nothing is lost and failback is one command.

**Watch (Claude, profile `sunshine-ledger`):**

```bash
P="--profile sunshine-ledger --region us-east-2"
aws cloudwatch describe-alarms $P --alarm-names sunshine-ledger-api-down --query 'MetricAlarms[0].[StateValue,StateUpdatedTimestamp]' --output text
ID=$(aws ec2 describe-instances $P --filters Name=tag:role,Values=standby --query 'Reservations[0].Instances[0].InstanceId' --output text)
aws ec2 describe-instances $P --instance-ids "${ID}" --query 'Reservations[0].Instances[0].[State.Name,LaunchTime]' --output text
curl -s https://sunshineledger-api.josephbernal.com/health      # read_only flips to true when the standby serves
```

- **T1:** alarm ALARM
- **T2:** "failover started" email, instance `running`
- **T3:** first `"read_only":true` from the public `/health`; the site shows the banner

**Checks while failed over (5 min):**
1. Open a bill page, the home page, an official's page. They should load with the "backup copy" banner.
2. Try "Report a problem" on a bill. It should refuse politely (503), not error.
3. Boot timings for the image decision. Run `aws ssm start-session --target $ID`, then:

   ```bash
   sudo journalctl -u sunshine-standby -o short-iso | grep -E "mode:|settings from SSM|downloaded|restore:|up: |joined the Cloudflare tunnel|FAILED"
   ```

   Record when each happened:
   - `mode: failover` (boot)
   - `downloaded` (dump fetched)
   - `restore:` (restore done)
   - `up: api` / `up: site`
   - `joined the Cloudflare tunnel`

   A failover boot does not build images. It uses what the last weekly refresh built, so the time goes to the boot, the dump download and the restore.

**T4: bring home back.** On docker-host:

```bash
docker start sunshineledger-cloudflared-1 sunshineledger-cloudflared2-1
```

- **T5:** alarm OK
- **T6:** "failover ended" email, instance `stopped`, tag `standby-mode=refresh`

Expect a few minutes where both origins are connected and Cloudflare splits
traffic between them. That's the known window, and reads are fine either way.

## Rollback (any time)

- **Standby misbehaving:** stop it by hand, then set it back to refresh mode:

  ```bash
  aws ec2 stop-instances $P --instance-ids "${ID}"
  aws ec2 create-tags $P --resources "${ID}" --tags Key=standby-mode,Value=refresh
  ```
- **Home tunnel won't come back:** run `docker start sunshineledger-cloudflared-1 sunshineledger-cloudflared2-1`, then check `docker logs --tail 50 sunshineledger-cloudflared-1`. The compose project lives in the Woodpecker checkout, not in your home folder, so use container names.
- **Alarm stuck in ALARM:** check the bridge is publishing:

  ```bash
  aws cloudwatch get-metric-statistics $P --namespace SunshineLedger/Uptime --metric-name Healthy --dimensions Name=Check,Value=sunshine-ledger-api --start-time $(date -u -v-30M +%FT%TZ) --end-time $(date -u +%FT%TZ) --period 300 --statistics Minimum
  ```

  This is the 11-26 failure mode: no data counts as down.
- **Standby keeps running:** set `automation=disabled`, stop it by hand, and file a finding.

## Decisions this test makes

- **Prebuilt images (ECR + CodeBuild, 6j5J6RH6m5GRmPGp).**
  - If T3 − T2 (start to serving) is **under 15 min**: images built by the weekly refresh are fast enough. Close the ticket as not needed and save the ~$1-2/month.
  - If it's over 15 min, look at where the time went. A failover never builds images; it uses the ones the weekly refresh built. So prebuilt images only help if the refresh's build is failing or the images were lost. If the restore dominates, see the restore-time item below instead.
- **Static S3 + CloudFront mirror (6j5J7W7JXr5Wmj6p).**
  - If check 3 failed, or T3 − T0 is over 30 min: a static read-only mirror is worth building as a second layer.
  - Otherwise close it as not needed.
- **Restore time.**
  - If the restore is most of the boot time, consider a smaller standby dump (no news text, no snapshots) as a follow-up.
